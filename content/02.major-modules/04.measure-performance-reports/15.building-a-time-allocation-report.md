## Before you start

You need the **time tracking report** permission — the same one that gates **User Time Tracking**. Without it the report is not listed under **Analyze**. You also need access to the **Analyze** area itself.

This walkthrough builds a report answering *"how did our engineering time divide across epics last quarter, month by month?"* It takes a few minutes and ends with a saved view you can re-run whenever you need it.

---

## Step 1 — Open the report

1. Click **Analyze** in the left navigation.
2. Stay on the **Analytics** tab.
3. In the sidebar, under **Time**, click **Time Allocation Matrix**.

You land on the setup form. Unlike the other reports, this one does not run automatically — it needs a hierarchy before it has anything to show.

::alert{type="tip" title="There is a keyboard shortcut"}
Press **Cmd-K** (or **Ctrl-K**) and type *time allocation* to jump straight here from anywhere.
::

## Step 2 — Set the reporting period

Under **Monthly reporting period**, set **Start date** and **End date**.

The defaults are the **start of the current year** through the **end of the current month** — a year-to-date view.

The helper text under the dates states the two rules:

> Actual Time is grouped into calendar months in the organization timezone. A report can include up to 24 months.

### Partial months

Columns are whole calendar months. If your start date is not the 1st, or your end date is not the last day of its month, that column covers only part of the month. The report is explicit about it rather than quietly under-reporting:

- The column header gains a suffix: **Jan 2026 (Partial)**.
- A warning appears above the grid naming exactly what was left out, for example: *"Jan 2026 is partial; excluded Jan 1, 2026 through Jan 14, 2026 (14 days)."*

Only the first and last columns can ever be partial. Everything between them is a full month.

::alert{type="note" title="Pick whole months unless you have a reason not to"}
For allocation reporting, whole months compare cleanly and total correctly against payroll or invoicing periods. Use a partial range when you are looking at a specific window — a sprint, an incident, a client engagement — and want it bounded exactly.
::

## Step 3 — Define the row hierarchy

This is the part that shapes the report. Under **Row hierarchy**:

> Levels are evaluated from top to bottom. Item type names stay current when they are renamed.

### Level 1

1. **Item type** — choose your top level. For our example, **Epic**.
2. **Selection mode** — leave it on **All**.
3. **Root scope** — click **Choose items** and pick where to look. This is required when level 1 uses **All**, and it is what stops the report scanning your entire organization. Pick the workstream, product area, or portfolio you care about.

::alert{type="tip" title="Root scope is your main performance control"}
The report walks everything under the scopes you choose. A tight scope makes the report fast and readable; pointing it at your whole organization is the most common cause of hitting the 5,000-row cap.
::

### Level 2

1. Click **Add level**.
2. **Item type** — **Story**.
3. **Selection mode** — **All**.

Level 2 onward has no root scope: those items are found beneath the level above.

### Adding, reordering, removing

Each level is a card headed **Level 1**, **Level 2**, and so on, with **Move up**, **Move down**, and **Remove** buttons. **Remove** is disabled when only one level remains.

### Selecting specific items instead

Switch **Selection mode** to **Selected** and click **Choose items** to pick exact items for that level. Use this when you want a fixed comparison set — five named epics rather than everything in a workstream.

When a level uses **Selected**, its rows appear **in the order you picked them**, which is useful for a report that always presents the same branches in the same order.

### The rules for levels

| Rule | Message if you break it |
|---|---|
| At least one level | *Add at least one hierarchy level.* |
| No more than 15 | *Use no more than 15 hierarchy levels.* |
| Every level needs an item type | *Choose an available item type for level 2.* |
| No item type used twice | *Each hierarchy level must use a different item type.* |
| Each level must sit below the one above in your item-type hierarchy | *Task must be below Story in the item-type hierarchy.* |
| Root scope required when level 1 is **All** | *Choose at least one root scope when the first level uses All.* |

That fifth rule is the one that catches people. The levels must follow your organization's configured item-type hierarchy — you can go Epic → Story → Task, but not Task → Epic. They do **not** have to be adjacent: Epic → Task works fine if tasks live under stories, because the report looks for descendants at any depth.

Any problems are listed in a red box headed **Complete the report configuration**, and **Run report** stays disabled until they are resolved.

## Step 4 — Run it

Click **Run report**. You will see **Running report…**, then the grid.

Use **Back to setup** to change the configuration, and **Refresh** to re-run the same one against current data.

::alert{type="warning" title="Editing any setting clears the results"}
Changing a date, a level, or a selection invalidates the current results and returns you to setup. This is deliberate — a grid that no longer matches the form above it is worse than no grid. Results also expire after **30 minutes**, after which an amber banner offers **Rerun report**.
::

## Step 5 — Read the results

Start at the **Grand total** row pinned under the header — that is all the time in scope. Then:

- **Collapse everything** and read the top-level subtotals to see the big split.
- **Check the Total % column** for each branch's share of the whole.
- **Expand the branch that surprises you** and repeat one level down.
- **Scan left to right** on a row whose trend you care about.

Watch for two things:

- **Direct badges** on parent rows — time logged at a level where you expected it on children. Often a sign work is being logged at the wrong level.
- **Warning banners** — a partial period, or *"Some configured selections are unavailable or outside the selected hierarchy."* The latter means part of your configuration no longer resolves: an item was moved, archived out of scope, or you lost access to it.

### If the grid is empty

| Message | Meaning |
|---|---|
| **No matching items** — *No authorized items matched this hierarchy and date range.* | The hierarchy found nothing. Check the root scope and that your level item types match how your items are actually structured. |
| **No time recorded** — *Matching items were found, but they have no Actual Time in this date range.* | The structure is right; the hours are not there. Check the date range, and whether the team logs time on these items at all. |

The distinction is the useful part: the first is a configuration problem, the second is a data problem.

## Step 6 — Save it as a view

Click **Views** in the toolbar, then save. Give it a name and an optional description, and choose who sees it:

- **Visible only to you**
- **Visible to coworkers**

Saved views store the **configuration**, not the results — dates, levels, item types, selections. Opening one drops you on the setup form with everything filled in; you press **Run report** to get current numbers. That is what makes a monthly report repeatable: save it once, re-run it each month.

You can share a view by copying its link. Anyone who opens it lands here with your configuration applied.

::alert{type="note" title="Saving and running use separate permissions"}
The form notes this: *"Saving a view and running it use separate permissions."* Saving needs stored-view permissions on top of the report permission, so you may be able to run a report you cannot save, or the reverse.
::

### Views shared with you may need repair

Stored views are filtered through **your** item access before you see them. If a colleague's view references items you cannot read, those references are stripped, and you get an amber banner:

> Some saved report settings are unavailable or outdated. Review the configuration before running or saving it.

Re-pick the missing scope or items and run it. The stripping is deliberate — it stops a shared view disclosing the existence of items you are not allowed to see.

::alert{type="info" title="These views cannot be published to the customer portal"}
Unlike some stored views, a Time Allocation Matrix view cannot be shared with portal customers. It is an internal reporting surface only.
::

## Worked example: capitalization by product line

**Goal:** how much engineering time went into each product line last quarter, split by month, as percentages.

1. **Period** — 1 January to 31 March. Whole months, so no partial columns.
2. **Level 1** — item type **Epic**, mode **All**, root scope set to the **Product Development** workstream.
3. **Level 2** — item type **Story**, mode **All**.
4. **Run report.**
5. Collapse to level 1 and read the **allocation** rows — the per-month and range percentages per epic.
6. **Export** for the finance team ([see the export guide](/major-modules/measure-performance-reports/exporting-the-time-allocation-matrix)).
7. **Save the view** as *Quarterly capitalization*, visible to coworkers, and re-run it next quarter with new dates.

## Troubleshooting

| Problem | Likely cause |
|---|---|
| *This report is too large to display* | Over 5,000 rows. Narrow the root scope, drop the deepest level, or shorten the range. |
| Fewer rows than expected | Rows with zero hours are dropped. The items exist; the time was not logged. |
| *The item-type hierarchy for level 2 contains a cycle* | Your organization's item-type configuration has a loop. An administrator needs to fix the type hierarchy. |
| *Time allocation matrix hierarchy cannot be resolved uniquely* | An item is reachable by two different paths in your configuration. Simplify the scope so each item has one home. |
| Numbers differ from a colleague's | You have different item access. The report only sums items you can read. |
| *You no longer have access to run this report* | The report permission was removed from your role. |
