---
title: "The Suspended Queue"
description: "Some inbound mail is held back for safety instead of becoming a ticket. The Suspended tab is where you review what was held and why."
---

Not every email that reaches your support address should become a ticket. Auto-replies, spam, and messages that fail their sender checks would clutter your Inbox — or worse, create noise your team has to clean up. DevStride holds these back in the **Suspended** queue so a person can decide what to do with them.

::alert{type="info" title="Who sees it"}
The **Suspended** tab requires the **Manage Requesters** permission. Agents focused only on replying to customers won't see it. See [Permissions](/major-modules/service-desk/permissions).
::

## What lands here

Open **Service Desk → Suspended** for a table of held messages, showing **From**, **Subject**, **Reason**, and **Received**. The **Reason** explains why each message was held:

| Reason | What it means |
| --- | --- |
| **Auto-response** | The message looks like an automatic reply (an out-of-office or bounce), not a real request — held to prevent endless back-and-forth loops. |
| **Rate limited** | The sender sent an unusually high volume in a short time. |
| **Spam** | The message was flagged as likely spam. |
| **SPF failed / DKIM failed / DMARC failed** | The message failed an email authenticity check, meaning the sender's identity couldn't be verified. |
| **Blocked sender** | The message came from a requester you've [blocked](/major-modules/service-desk/requesters-and-companies). |

![The Suspended tab. When no mail is held, it shows a clean empty state; held messages appear here with From, Subject, Reason, and Received columns for triage.](/images/service-desk/suspended.png)

::alert{type="note" title="Some mail is dropped outright"}
A message carrying a virus, or an exact duplicate of one already processed, is discarded automatically and never appears in the queue — there's nothing useful to look at. The Suspended queue is only for messages a human might legitimately want to review.
::

## Reviewing what's held

Click a held message to open it. You'll see who sent it, its subject, why it was held, and a preview of the text.

Two actions are available:

- **Mark spam** — record it as spam and clear it from the queue.
- **Delete** — discard it.

::alert{type="note" title="Releasing a held message isn't available yet"}
**Release** and **View original** appear in the dialog but are switched off. Both need the retained copy of the original message, which is still being built — releasing has to re-run the message through the pipeline to create the ticket, and doing it any other way would take a customer's message out of triage having created nothing.

So a legitimate message that was held cannot be turned into a ticket from this screen today. Ask the sender to resend it, or fix whatever held it — usually their own domain's sender setup — so their next message comes straight through.
::

::alert{type="tip" title="Make it a habit"}
Skim the Suspended queue periodically so a real request that tripped a filter doesn't sit unanswered — it matters more while releasing isn't available, because a held message needs a person to notice it and follow up another way. If a particular trusted customer keeps getting held, fixing their sender setup (or confirming they're not blocked) usually stops it.
::
