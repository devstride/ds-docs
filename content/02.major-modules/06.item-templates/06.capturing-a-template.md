---
title: "Capturing an Existing Item as a Template"
description: "The fastest way to author a template: point at work that already has the right shape and export it, then vary the parts that should vary."
---

Most templates don't need to be drawn from nothing. You've almost certainly already run this job once — the shape is sitting in your map right now. **Save as Template…** exports it.

## How to do it

Right-click any workstream or work item and choose **Save as Template…**.

![The item right-click menu showing Apply Template… and Save as Template…](/images/item-templates/save-as-template-menu.png)

![The Save as Template dialog, naming the source and listing what will be captured.](/images/item-templates/save-as-template-dialog.png)

The dialog shows the **source** item, lets you name the template, and tells you exactly what is coming with it. The name defaults to the source item's title.

**Save & open builder** captures the subtree and drops you straight into the builder with it loaded.

## What gets captured

The whole subtree beneath the item you picked — every child, at every depth, including sub-items — comes across, along with each item's:

- title and description
- work type
- start and due dates
- assignee and team
- priority, tags and effort estimate
- custom-field values

What does **not** come across: statuses, boards, comments, attachments, relationships, calculated fields and Service Desk fields. A template describes work to be started, so it deliberately doesn't carry a snapshot of work already in flight.

## Everything arrives fixed

This is the important bit. A captured template has **every value set to Fixed** — no variables are inferred. Applied as-is, it would recreate the original almost exactly, dates and assignees and all.

That's the intended starting point, not the finished article. The dialog says so:

> *Values are saved as fixed. Open the builder to turn them into variables — for example, replace the start date with a date anchor and the named assignees with assignee slots.*

So the actual authoring workflow is:

1. **Capture** the shape from real work.
2. **Open the builder** and look for the values that were true of *that* instance rather than of the job in general — the client's name, last quarter's dates, whoever happened to run it.
3. **Promote those to [variables](/major-modules/item-templates/variables)** and delete anything instance-specific from the descriptions.
4. **Try it** to check the result, then **Share** it.

Steps 2 and 3 are usually five minutes' work, against half an hour of building the same tree by hand.

## Audience

A captured template is **private to you** at birth — you are its only owner, and nobody else can see it while you tidy it up. Sharing is a separate step in the builder once you're happy with it. See [Sharing templates](/major-modules/item-templates/sharing-templates).

## The original is untouched

Capturing reads the subtree; it never modifies it. The source workstream and its items carry on exactly as they were, with no marker, no link and no lock. Equally, editing the template afterwards has no effect on the work you captured it from.
