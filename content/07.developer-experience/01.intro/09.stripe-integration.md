# Stripe Integration

DevStride uses Stripe for subscription billing. The `ds stripe` CLI (`cli/commands/stripe.ts`) wraps three commands: provisioning Stripe products, exporting a read-only inventory of what Stripe holds for every customer, and proving the one-off invoice flow against a test-mode key. It is a thin operational tool, not a sync engine — each command does one specific thing, and none of them run on a schedule.

::alert{type="warning" title="Billing is moving to DevStride"}
DevStride is taking the billing schedule away from Stripe: DevStride will decide who is on trial, who pays and who is locked, while Stripe keeps holding cards, processing them and storing payment history. The first step of that move has shipped — a safety fence that stops Stripe's webhook from overwriting a customer DevStride manages. It is dormant today, because no customer is managed by DevStride yet.

Two commands this page used to document are **gone**: `create-customers` (which subscribed organizations to the free plan) and `find-subscription-quantity` (which audited seat drift). Their replacement is `billing-inventory` below.
::

::alert{type="info" title="Prerequisites"}
Like every `ds` command, `ds stripe` goes through the standard AWS SSO gate before running. The commands themselves call the Stripe API directly using `STRIPE_SECRET_KEY`, one of the values you fill in by hand in `.env` and push up with `ds script set-config` — see [Getting Started](/developer-experience/intro/getting-started).
::

## Add Products

```bash
ds stripe add-products
```

### What It Does

Creates three Stripe products, each with a monthly and a yearly price, and a matching DevStride product record (via `CreateProductCommand`) with its default usage limits:

| Product | Monthly / Yearly price | Default | Notes |
|---|---|---|---|
| **Professional** | $9.00 / $90.00 | — | 100 smart suggestions, 1,000 actions, 1 GB storage |
| **Business** | $24.00 / $240.00 | Default product | 1,000 smart suggestions, 300,000 actions, 5 GB storage |
| **DevStride Free** | $0 / $0 | Marked custom | Same limits as Business |

::alert{type="warning" title="Not idempotent"}
`add-products` always calls `stripe.products.create` — it does not check whether a product with that name already exists. Running it twice creates duplicate products in Stripe. Run it once per Stripe account/stage, not as a routine sync.
::

**When to run:**
- Bootstrapping a brand-new stage's Stripe account for the first time
- If a stage's Stripe products need to be (re)created from scratch

Run it once when bootstrapping a stage's Stripe account. Nothing calls it automatically any more.

## Billing Inventory

```bash
ds -b stripe billing-inventory --out <directory outside the repository>
```

### What It Does

Exports, **read-only**, everything Stripe holds for every customer beside DevStride's own view of the same customer — the census the billing migration is planned from, and the check run again before the old subscription code is deleted. Every Stripe call it makes is a list; it changes nothing, in Stripe or in DevStride.

It writes one row per billable organization to `inventory.csv`, plus the raw records it read as JSON Lines: `organizations.jsonl`, `subscriptions.jsonl`, `customers.jsonl`, `unsettled-invoices.jsonl`, `pending-invoice-items.jsonl` and `catalogue.jsonl`.

`inventory.csv` puts DevStride's stored status, seats and price beside Stripe's, compares seat counts three ways (stored, recomputed, Stripe), and carries renewal and trial dates, hand-extended trials, paused collection, the latest invoice status, scheduled changes in words, whichever payment method Stripe would actually charge, the invoice email, and a `note` column naming anything a person needs to look at.

::alert{type="warning" title="It refuses a full secret key, and refuses to write inside the repository"}
The export needs `STRIPE_INVENTORY_KEY`, and that must be a **restricted** key (`rk_…`) with read access only — a full `sk_…` secret key is rejected. `--out` must also resolve outside this repository: the files hold customer names, invoice emails and negotiated prices, and the repo has no ignore rule for them. Do not work around either refusal.
::

The files are written readable by you alone, and the command will not follow a symlink or write into a directory that resolves inside the repository. In `inventory.csv`, any name or email beginning with `=`, `+`, `-` or `@` carries a leading apostrophe so a spreadsheet cannot execute it as a formula.

::alert{type="note" title="Match the key to the stage"}
A test-mode key pointed at production organizations joins nothing: every row reads "Stripe customer not found in this Stripe account", which looks alarming and only means the wrong key.
::

**When to run:**
- Taking a census of real billing state before changing anything
- Re-checking that census before the old Stripe subscription code is removed

## Prove Invoice Flow

```bash
ds -b stripe prove-invoice-flow
```

### What It Does

Exercises the one-off invoice flow — the primitive DevStride-owned billing will charge with — against Stripe **test mode**, so the behaviour is proven on the pinned Stripe SDK version rather than assumed. It needs `STRIPE_PROOF_KEY`, a test-mode key.

**When to run:** before relying on one-off invoice behaviour in a change, or after a Stripe SDK or API version bump.
